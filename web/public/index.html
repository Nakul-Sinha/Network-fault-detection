      How it works

      Five stages, deliberately boring at the bottom and only as clever as it needs to be at the top.

      1. L0

        Rules

        Gateway unreachable, DNS blackholed, a sign-in page intercepting everything. Also suppression: while a captive portal is up, no other layer may be blamed. A threshold beats a model when the answer is already certain.

      2. L1

        Seasonal statistics

        Is this unusual for this network, at this time of day. Home networks have strong daily rhythms, so a single average would flag every weeknight. Learning freezes while something looks wrong, or a sustained fault teaches the baseline to accept itself.

      3. L2

        Online autoencoders

        One small model per layer, trained continuously, no labels anywhere. Catches unusual combinations that per-feature statistics miss.

      4. L3

        The forecast

        A calibrated logistic regression per horizon, weighted toward slopes rather than levels. A latency that is high and steady is one you have adapted to. A latency that is climbing is the one that breaks the call.

      5. L4

        Attribution

        Latency propagates outward, so ranking raw anomaly scores blames the far end for a Wi-Fi problem every time. Each layer's score is reduced by what its upstream layers already explain, then the cross-layer ratios vote.

      The privacy claim is structural

      Not a policy you have to trust. A property of the schema you can check.

      $ sqlite3 netpulse.sqlite ".schema samples"
CREATE TABLE samples (
  ts REAL PRIMARY KEY,
  "wifi_rssi_dbm" REAL,
  "gw_rtt_ms"     REAL,
  "dns_p50_ms"    REAL,
  ...
);

      Every column is a number. There is nowhere to put a hostname, a URL or a packet byte, so the agent could not store your browsing history if it tried. A test asserts this against the live schema on every run.

      • No packet capture, at any setting
      • Network names stored as a salted hash, never in the clear
      • Every probe it sends is written to a ledger you can read
      • No account, no telemetry, no cloud
      • One command deletes everything

      It is an active tool, so it does send probes: your router, your resolver, and a short list of HTTPS endpoints you can change or switch off entirely. All of it is listed in the privacy document.

      Run it on your own machine

      This page is a recording. The real thing measures your network, which is the only place this measurement means anything. 

      $ pip install netpulse-local

$ netpulse doctor        # what can this machine measure?
$ netpulse check         # one full round, then exit
$ netpulse run           # agent + web UI on 127.0.0.1:8787
$ netpulse demo          # replay a fault against the live UI

      What this is not

      Not an enterprise monitor, not an intrusion detector, not a packet capture tool. It has one vantage point, your machine, so it can say trouble appeared past your router but it cannot prove whose fault that is. Every incident card is worded that way, and always will be. The scenarios on this page are synthetic by necessity: they say the system behaves correctly on faults of the kind it was designed for, not that it will behave this way on your network.
