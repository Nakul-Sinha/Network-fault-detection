predicts network trouble minutes before you feel it, names the failing layer, and never sends anything off your machine · v0.1.0 · Apache-2.0

visitor@netpulse:~$ cat about.txt

A call freezes. A game lags. A page stalls. Nothing tells you whether it was the Wi-Fi, DNS, your router or your internet provider, and most tools only speak up after it already broke.

NetPulse Local watches seven layers at once on your own machine, forecasts degradation five to fifteen minutes ahead, and explains which layer is failing in a sentence you can act on.

visitor@netpulse:~$ cat architecture.txt


    

      Five stages, deliberately boring at the bottom and only as clever as it needs
      to be at the top.
    


    
    
      
  1. 
        [L0]
        
    
          
    rules
    
          
    
            Gateway unreachable, DNS blackholed, a sign-in page intercepting everything.
            Also suppression: while a captive portal is up, no other layer may be blamed.
            A threshold beats a model when the answer is already certain.
          
    
        
    
      
    2. 
      
  2. 
        [L1]
        
    
          
    seasonal statistics
    
          
    
            Is this unusual for this network, at this time of day. Home networks
            have strong daily rhythms, so a single average would flag every weeknight.
            Learning freezes while something looks wrong, or a sustained fault teaches
            the baseline to accept itself.
          
    
        
    
      
    3. 
      
  3. 
        [L2]
        
    
          
    online autoencoders
    
          
    
            One small model per layer, trained continuously, no labels anywhere. Catches
            unusual combinations that per-feature statistics miss.
          
    
        
    
      
    4. 
      
  4. 
        [L3]
        
    
          
    the forecast
    
          
    
            A calibrated logistic regression per horizon, weighted toward slopes rather
            than levels. A latency that is high and steady is one you have adapted to.
            A latency that is climbing is the one that breaks the call.
          
    
        
    
      
    5. 
      
  5. 
        [L4]
        
    
          
    attribution
    
          
    
            Latency propagates outward, so ranking raw anomaly scores blames the far end
            for a Wi-Fi problem every time. Each layer's score is reduced by what its
            upstream layers already explain, then the cross-layer ratios vote.
          
    
        
    
      
    6.

      Every column is a number. There is nowhere to put a hostname, a URL or a packet
      byte, so the agent could not store your browsing history if it
      tried. A test asserts this against the live schema on every run.
    


    
    
      
  • No packet capture, at any setting
    • 
      
  • Network names stored as a salted hash, never in the clear
    • 
      
  • Every probe it sends is written to a ledger you can read
    • 
      
  • No account, no telemetry, no cloud
    • 
      
  • One command deletes everything
    • 
    


    

      It is an active tool, so it does send probes: your router, your
      resolver, and a short list of HTTPS endpoints you can change or switch off
      entirely. All of it is listed in
      docs/privacy.md.

what this is not

      

        Not an enterprise monitor, not an intrusion detector, not a packet capture tool.
        It has one vantage point, your machine, so it can say trouble appeared past your
        router but it cannot prove whose fault that is. Every incident card is worded
        that way, and always will be. The scenarios above are synthetic by necessity:
        they say the system behaves correctly on faults of the kind it was designed for,
        not that it will behave this way on your network.
